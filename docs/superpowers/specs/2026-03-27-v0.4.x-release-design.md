# FlowFolio 0.4.x Release Design — "Solid Ground"

**Date:** 2026-03-27
**Status:** Approved
**Author:** Brainstormed with Claude Code

---

## Overview

FlowFolio 0.4.x makes the project's own promises true. The README advertises "privacy-first, zero telemetry, API keys secured via Tauri Stronghold" — none of those are fully true at the end of 0.3.x. This release series fixes that, ships on mobile (iOS + Android), removes all aspirational scaffolding, and establishes a test foundation for financial calculations.

**Structure:**
- **0.4.0** — Big drop: four parallel tracks, all land together
- **0.4.1 → 0.4.3** — Focused patch series after 0.4.0 ships

---

## 0.4.0 — "Solid Ground"

Four independent tracks run in parallel. 0.4.0 ships when all four pass their done criteria.

### Track 1 — Security: Keys Out of the Bundle

**Problem:** All 9 market data API keys + OpenRouter key use `VITE_*` prefix, embedding them in the compiled JS bundle. `SecurityManager` (`src-tauri/src/modules/security/mod.rs`) is a complete stub. `tauri-plugin-stronghold` is in `Cargo.toml` but unwired.

**Changes:**

1. Strip `VITE_` prefix from all API keys — they become backend-only env vars read via `dotenvy`.
   - Affected keys: `ALPACA_API_KEY`, `ALPACA_API_SECRET`, `FINNHUB_API_KEY`, `FMP_API_KEY`, `TIINGO_API_KEY`, `TWELVE_DATA_API_KEY`, `POLYGON_API_KEY`, `ALPHAVANTAGE_API_KEY`, `YAHOO_FINANCE_API_KEY`, `OPENROUTER_API_KEY`

2. Complete `SecurityManager` — implement `store_api_key` / `get_api_key` using `tauri-plugin-stronghold`. On first run, migrate keys from `.env` into Stronghold. On subsequent runs, read from Stronghold only.

3. Add Tauri command `get_api_keys_status` — returns which providers are configured (boolean per provider), never the key values. Used by Settings page.

4. Update `SettingsPage.tsx` — add a key entry UI that calls `store_api_key` command. Key values never persist in React state beyond the input field.

5. Reroute `portfolioAgent.ts` LLM calls through the existing `src-tauri/src/api/commands/ai.rs` command. Remove `VITE_OPENROUTER_API_KEY` from the frontend entirely.

6. Update `DataSourcesPage.tsx` — show provider health status and link to Settings for key management.

**Done criteria:**
- `grep -r "VITE_.*KEY" src/` returns zero results
- `SecurityManager` has working Stronghold read/write (with unit test)
- App works end-to-end with keys stored only in Stronghold

### Track 2 — Mobile: iOS + Android Builds

**Problem:** The app is desktop-only. Tauri 2 supports mobile but the targets are not initialized. `llama_cpp` has `features = ["metal"]` which breaks Android builds. No responsive CSS exists.

**Changes:**

1. Fix `llama_cpp` Metal feature flag — gate with `#[cfg(any(target_os = "macos", target_os = "ios"))]`. Android gets local AI disabled at runtime with a graceful "not available on mobile" message.

2. Initialize Tauri mobile targets — run `tauri ios init` and `tauri android init`, commit generated `ios/` and `android/` directories.

3. Add CSS responsive breakpoints at 768px and 390px (iPhone SE minimum). Tab bar becomes bottom navigation on mobile. Cards stack vertically. This is minimum-viable, not polished — polish is 0.4.1.

4. Touch target audit — all interactive elements must be ≥44×44pt (Apple HIG). Fix worst offenders in VibeStudio, PortfolioTab, and the main tab bar.

5. Add capability check for local AI — `portfolioAgent.ts` detects mobile platform and shows degraded mode message instead of calling llama.cpp.

6. Update `tauri.conf.json` with mobile-specific capability configs (filesystem paths differ on iOS/Android).

**Done criteria:**
- `npm run tauri ios build` succeeds
- `npm run tauri android build` succeeds
- App launches on iOS Simulator and Android Emulator
- Core flows work: view portfolio, run backtest, open VibeStudio

**Out of scope (→ 0.4.1):**
- Beautiful mobile UI, bottom nav, swipe gestures
- App Store / Play Store submission
- Push notifications

### Track 3 — Polish: No Stubs, No Broken Features

**Problem:** `PremiumGate` gates features behind a non-existent paywall. `worker_pool` is dead code. Onboarding may be unwired. Empty states are missing. Error boundaries are not consistently applied.

**Changes:**

1. **Remove `PremiumGate`** — delete `src/components/PremiumGate.tsx` and `PremiumGate.css`. Replace every usage with the actual gated feature content.

2. **Remove `worker_pool` module** — verify with `grep -r "worker_pool" src-tauri/src/` and delete if unused. It was previously identified as dead in commit `57f6c87`.

3. **Wire onboarding** — audit `src/features/onboarding/`. If complete, connect to first-run experience. If stub, implement minimum 3-step flow: Welcome → Add API Keys (links to Settings) → Done. Do not build a complex onboarding wizard.

4. **Fix `DataSourcesPage`** — redesign to show per-provider status (configured/not configured, last successful fetch, rate limit state). Data comes from `get_api_keys_status` (T1) and existing cache stats command.

5. **Empty state audit** — every tab must show a helpful empty state with a CTA when data is absent. No blank screens, no JS errors on empty arrays.

6. **Error boundary coverage** — verify every top-level tab is wrapped in `TabErrorBoundary`. Add any missing wrappers.

7. **`RateLimitBanner` verification** — confirm it actually renders when the Rust rate limiter fires, not just statically present in the tree.

8. **`tauri-plugin-notification` decision** — wire it for 2 meaningful events (backtest complete, rate limit hit) or remove the dependency. No unused deps.

**Done criteria:**
- `grep -r "PremiumGate" src/` returns zero results
- First-run experience has an onboarding flow
- No tab renders a blank screen on empty data
- Every top-level tab is wrapped in an error boundary

---

### Track 4 — Tests: Financial Math is Verified

**Problem:** Zero frontend tests. Vitest not configured. Rust unit test coverage is minimal. `npm test` in CI has nothing to run. Financial calculations are unverified.

**Changes:**

1. **Configure Vitest** — add `vitest` + `@vitest/coverage-v8` to `devDependencies`. Add `"test": "vitest run"` and `"test:coverage": "vitest run --coverage"` to `package.json`. No config file needed for a Vite project.

2. **Test `shared/utils/calculations.ts`** — unit tests for every exported function. Edge cases: zero values, negative returns, empty arrays, NaN inputs. Target: ≥90% coverage.

3. **Test Rust quant functions** — `#[cfg(test)]` modules in `src-tauri/src/modules/quant_analysis.rs`. Tests: Sharpe ratio, max drawdown, annualized return, volatility — all with fixed known inputs and expected outputs.

4. **Test backtest engine core** — `src-tauri/src/modules/backtest/` — test return calculation with a simple hardcoded price series (e.g. buy at 100, sell at 150 = 50% return). No live data.

5. **Test plan compiler** — `src-tauri/src/modules/plan_compiler/` — test valid and invalid vibe plan script inputs. This is the highest-risk panic surface for bad user input.

6. **CI coverage gate** — add coverage threshold to existing CI: frontend ≥80% on `shared/utils/`, all Rust tests must pass.

**Done criteria:**
- `npm test` exits 0 with ≥1 test suite
- `cargo test` exits 0 with ≥10 unit tests
- `shared/utils/calculations.ts` has ≥90% line coverage
- Rust quant + backtest core have deterministic unit tests

## Patch Series: 0.4.1 → 0.4.3

### 0.4.1 — "Native Feel" (Mobile UI Adaptation)

The 0.4.0 mobile build works but looks like a desktop app on a phone. This patch makes it feel native.

- Bottom tab navigation on mobile (replaces horizontal tab bar)
- Swipe gestures for tab switching
- Charts made touch-friendly (larger tap areas, pinch-to-zoom on Recharts)
- Typography scaling for small screens
- VibeStudio factor sliders adapted for touch input
- Test on physical devices (not just simulators)

### 0.4.2 — "Fast Everywhere" (Performance Profiling)

Mobile surfaces performance problems desktop hides. Fix the top bottlenecks found on real devices.

- Profile app startup time on mid-range Android device
- Identify and fix top 3 render bottlenecks (likely: heavy chart re-renders, large portfolio list virtualization)
- SQLite query profiling — `EXPLAIN QUERY PLAN` audit for the 5 most frequent queries
- Reduce initial bundle size further (follow-up on Vite code splitting from 0.3.x)

### 0.4.3 — "Battle-Tested" (Test Coverage + CI Hardening)

Expand the test foundation from 0.4.0.

- Frontend: integration tests for main user flows (create portfolio → run backtest → view results)
- Backend: test all 9 API command handlers with mocked market data
- Add `cargo clippy -- -D warnings` to CI
- Wire `security_check.sh` into CI preflight

## What Does NOT Ship in 0.4.x

- No new features beyond what already exists in the UI
- No new data providers
- No AI model upgrades (llama.cpp/Qwen stays as-is)
- No App Store / Play Store submission (0.5.x)
- No premium tier (PremiumGate removed entirely)
