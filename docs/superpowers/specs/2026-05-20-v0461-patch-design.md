## 3. Backend Changes

### 3.1 Input validation (Rust) — `src-tauri/src/api/commands/options.rs:6-42`

Add a private helper:

```rust
fn validate_new_position(
    strike: f64,
    contracts: i64,
    premium_per_contract: f64,
    expiration: &str,  // YYYY-MM-DD
    open_date: &str,
) -> Result<(), String> {
    if strike <= 0.0 { return Err("strike must be > 0".into()); }
    if contracts <= 0 { return Err("contracts must be > 0".into()); }
    if premium_per_contract < 0.0 { return Err("premium cannot be negative".into()); }
    let exp = chrono::NaiveDate::parse_from_str(expiration, "%Y-%m-%d")
        .map_err(|_| "expiration must be YYYY-MM-DD".to_string())?;
    let today = chrono::NaiveDate::parse_from_str(open_date, "%Y-%m-%d")
        .unwrap_or_else(|_| chrono::Utc::now().date_naive());
    if exp < today { return Err("expiration must be on or after open date".into()); }
    Ok(())
}
```

Call from `create_option_position` immediately after the `strategy` whitelist check. Frontend rejection is a UX nicety; backend validation is the truth.

### 3.2 `aggregate_options_summary` clarity refactor — `options.rs:141-179`

**Current state:** helper computes both `total_cash_secured` and `total_assignment_exposure` for every open row; caller in `get_options_summary` reads `csp_summary["total_cash_secured"]` and `cc_summary["total_assignment_exposure"]` — correct *by selection*, not by computation.

**New signature:**

```rust
pub(crate) fn aggregate_options_summary(
    rows: &[(String, f64, i64, f64, Option<f64>)],
    strategy: &str,  // "covered_call" or "cash_secured_put"
) -> Value
```

Inside the helper: only the relevant exposure field is populated.

- `"covered_call"` → set `total_assignment_exposure += notional` for open rows; `total_cash_secured = 0`.
- `"cash_secured_put"` → set `total_cash_secured += notional` for open rows; `total_assignment_exposure = 0`.

`realized_premium_ytd` aggregates regardless of strategy. Update both call sites in `get_options_summary`. Existing `#[cfg(test)] mod tests` cases must be updated to pass the new parameter; add one mixed-strategy fixture case.

### 3.3 Dividend negative cache — `src-tauri/src/modules/dividend_calendar/mod.rs`

Cache row contract today: write only when `!divs.is_empty()`.

**New contract:**
- Always write after a provider call.
- Empty result → store `dividend_data_json = "[]"` with `expires_at = now + 6h`.
- Non-empty → existing 24h TTL.
- Read: if row exists AND `now < expires_at`, return it. Empty list is a **hit**, not a miss.

No schema change — only behavior at write/read time.

### 3.4 Bounded-concurrency parallelization — `dividend_calendar.rs:205+` (`get_upcoming_dividends`)

```rust
use futures::stream::{self, StreamExt};
let results: Vec<_> = stream::iter(symbols.iter())
    .map(|sym| fetch_one_with_cache(sym.clone(), pool.clone(), providers.clone()))
    .buffer_unordered(5)
    .collect()
    .await;
```

Bound = 5 (keeps under Finnhub 60/min ceiling even with 30 holdings + retries).

### 3.5 Shares-adjusted projection

Replace existing 1:1 stub:

```rust
projected_annual = trailing_dividend_per_share * current_shares
```

- `trailing_dividend_per_share` = sum of last 4 quarterly events (or last 12 monthly) from cache.
- `current_shares` = the snapshot value already joined into the response from `holdings`.

Same join provides the per-row `projected_payout = amount_per_share × shares_held` returned by `get_upcoming_dividends` (item 8).

### 3.6 Finnhub header auth + FMP error scrubbing — `dividend_calendar/mod.rs`

- Finnhub: replace `?token={key}` query param with `X-Finnhub-Token: {key}` header on the `reqwest::Client` request builder. Smoke-test against `/calendar/earnings` and the dividend endpoint before shipping.
- FMP: keep query auth (no header support). In `map_err` paths that surface to frontend, scrub:

```rust
.map_err(|e| {
    let s = e.to_string();
    if s.contains("apikey=") {
        format!("FMP request failed: {}", e.status().map(|c| c.to_string()).unwrap_or_else(|| "unknown error".into()))
    } else { s }
})
```

Test: provoke a 401 with a fake key and assert the error string does not contain `apikey=`.

### 4.1 `useWashSaleStatus` hook — `src/hooks/useWashSaleStatus.ts` (new)

```ts
type WashSaleStatus = 'safe' | 'window' | 'unknown';
```

**Consumers:**
